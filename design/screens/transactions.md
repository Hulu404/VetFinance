# Экран «Транзакции» (этап 1)

Все движения денег клиники в одном списке: из банка (выписка 1С), Ветменеджера и внесённые вручную. Здесь человек разносит операции по статьям, разбирает дубли и добавляет то, чего нет в выписке. Функции 6–9. Источник внешнего вида: v6 `vTx` (карточки итогов `.mcard`, вкладки `.seg`, таблица `table` в `.card`). Компоненты: `components.md` (разделы 1–14). Оболочка: `shell.md`.

Решения владельца: экраны берём из v6, нового не рисуем; ролей, бота и ИИ нет. Функция 7 «На проверку» в MVP работает по правилам и по поиску похожих операций с тем же контрагентом, без ИИ-подсказок и без слова «ИИ» на экране.

Gate этапа (из `docs/stages.md`), что видит пользователь: повторная загрузка того же файла ничего не удваивает; правило разнесения применяется к новым операциям; дубли найдены.

Подсказка у «Сальдо» в v6 нет; добавлена по правилу 4. Подпись «Сальдо» в v6 называется так же; в подсказке то же слово, без «баланс», чтобы не путать с остатком на счетах.

Клиент не считает: итоги, остатки, количество применений правила, разницу между группами. Допустимо клиенту: форматирование, склонение, сортировка по уже полученным полям, перенос между страницами.

## Шапка и действия

Слот действий (правая часть `.head`): `primary` «+ Операция» (v6) открывает форму ручной операции; `secondary` «Загрузить выписку» открывает диалог загрузки. На 390 слот уходит под заголовок, две кнопки в одной строке по 50% ширины, 44px (если не помещаются, друг под другом). Оба действия видны на всех вкладках.

## Период

Над итогами: `‹  Сентябрь 2026  ›` (заголовок 17px / 700 как в v6 `.calbar b`, две кнопки `secondary` 40×40 (44 на мобильном) с `‹` и `›`, имена «Предыдущий месяц», «Следующий месяц»). Следующий месяц отключён, если выбран текущий (по `as_of`). Месяц хранится в адресе (`?month=2026-09`), по умолчанию месяц из `as_of`.

Месяц управляет итогами и вкладкой «Все» (`from` и `to` = первый и последний день месяца). Вкладки «На проверку» и «Дубли» показывают операции за все месяцы (операция без статьи остаётся проблемой, даже если она из прошлого месяца), под вкладкой строка 13px `--color-ink-soft`: «Показаны операции за все месяцы.» Свой диапазон дат («с … по …») на этапе 1 не делаем: итоги сводятся по месяцам, и диапазон создавал бы число, которое не совпадает с итогами. Вопрос владельцу в `docs/handoff.md`.

Дата месяца в подписях карточек: «Доходы за сентябрь», «Расходы за сентябрь» (родительный падеж строчными).

## Правка статьи и создание правила

Открывается из: кнопки «Выбрать статью» (вкладка «На проверку»), плашки статьи (вкладка «Все»), кнопки «Другая статья» (если есть предложение).

### Предложение статьи (без ИИ)

Если backend прислал `suggestion` (запрос к backend: статья из уже действующего правила или статья, которой разнесены похожие операции того же контрагента), строка во вкладке «На проверку» выглядит так:

```
Дата  Операция                                 Статья        Сумма        Действие
7 сен ИП Волков · аренда за сентябрь           без статьи    −85 000 ₽    [ Подтвердить: Аренда ]
      Т-Банк · 7972 · Банк                                                [ Другая статья ]
      Предлагаем «Аренда»: так же разнесено 3 операции по «ИП Волков»
```

«Подтвердить» сразу сохраняет предложенную статью (`PATCH` с `category_id` из предложения). Если предложение основано на правиле (`suggestion.reason = rule`), новое правило не создаётся. Если основано на похожих операциях без правила (`reason = similar`), создаётся правило (`create_rule: true`), потому что цель функций 7 и 9 в том, чтобы человек поправил один раз. Текст в тосте это показывает (ниже). Без `suggestion` в строке одна кнопка «Выбрать статью» и нет строки «Предлагаем…». Текст предложения собирает backend (поле `suggestion.text`), клиент его не склеивает.

### Диалог «Статья для операции»

Диалог (раздел 9, ширина 480). Содержимое:

1. Заголовок «Статья для операции».
2. Сводка операции в блоке `--color-accent-faint`, `--radius-lg`, отступы 12px 14px: описание (14px, 600, до 2 строк), под ним «7 сентября · Т-Банк · 7972 · Банк» (12px), справа сумма (с подсказкой не нужна: подсказка уже на экране под диалогом; в диалоге сумма просто текст).
3. Поле `CategoryField` с подписью «Статья». Если у операции уже была статья, выбрана она. Для `kind = in` в списке доходы, для `out` расходы.
4. Флажок «Создать правило для похожих операций». Включён по умолчанию (v6: «правила создаются сами, когда вы поправляете категорию вручную»).
5. Под флажком строка правила (12,5px, `--color-ink-soft`), меняется по состоянию:

| Состояние | Текст |
| --- | --- |
| Статья не выбрана | «Выберите статью, и мы покажем, к скольким операциям применится правило.» |
| Идёт расчёт | Заглушка 70% ширины × 13px |
| Флажок включён, есть совпадения | «Правило: если контрагент «ИП Волков», статья «Аренда». Применится к 3 уже загруженным операциям без статьи и ко всем новым.» |
| Флажок включён, совпадений сейчас нет | «Правило: если контрагент «ИП Волков», статья «Аренда». Сейчас других таких операций без статьи нет, правило сработает на новых.» |
| Флажок выключен | «Изменится только эта операция.» |
| Правило создать нельзя (`can_create = false`) | Флажок отключён, строка: «Для этой операции правило не создать: у платежа не определён контрагент.» |
| Ошибка расчёта | «Не получилось посчитать, к скольким операциям применится правило. Оно всё равно создастся.» |
| Такое правило уже есть | Флажок отключён, строка: «Такое правило уже есть, оно применилось бы к этой операции автоматически. Проверьте вкладку «Правила разнесения».» |

Числа в строке правила («3 операциям») берутся из ответа превью (`matches_count`), клиент их не считает. Это превью, а не итог, поэтому подсказки у числа нет; итог после сохранения показан в тосте и во вкладке правил (с подсказкой).

6. Кнопки: `secondary` «Отмена», `primary` «Сохранить». Выполняется: «Сохраняем…».

Ошибка сохранения: блок ошибки над кнопками: «Не получилось сохранить статью. Операция осталась как была. Попробуйте ещё раз.» Если операция уже изменена другим способом (`conflict`): «Эта операция уже изменилась. Обновите список и повторите.» с кнопкой `text` «Обновить список».

### После сохранения: как видно, что правило создано

1. Диалог закрывается, фокус на заголовок списка (строка, скорее всего, исчезла из вкладки «На проверку»).
2. Тост (8 секунд), в зависимости от ответа `PATCH` (поле `rule`, запрос к backend):

| Случай | Текст тоста | Действие в тосте |
| --- | --- | --- |
| Правило создано, применилось к N операциям кроме этой | «Статья «Аренда» сохранена. Правило создано и применилось ещё к 3 операциям.» | «Посмотреть правило» открывает вкладку «Правила разнесения», новое правило подсвечено |
| Правило создано, других операций нет | «Статья «Аренда» сохранена. Правило создано: новые такие операции будут разноситься сами.» | то же |
| Правило не создавали | «Статья «Аренда» сохранена.» | нет |
| Подтверждено предложение по правилу | «Статья «Аренда» сохранена.» | нет |

3. Счётчик вкладки «На проверку» уменьшается (запрос счётчиков перезапрашивается). Если вкладка пуста, показывается пустое состояние.
4. Во вкладке «Правила разнесения» новая строка наверху на 3 секунды в фоне `--color-accent-soft` (при `prefers-reduced-motion` без плавной смены, просто фон до конца 3 секунд), `aria-live` не используется, текст тоста уже озвучен.
5. Правило (контрагент по ИНН → статья) применяется к новым операциям и к уже загруженным без статьи или со статусом «на проверку». Операции, разнесённые вручную, оно не трогает (решение владельца). Число в превью и в тосте это только такие операции.

Откат: кнопки «Отменить» в тосте нет (журнал с откатом приходит на этапе 7). Статью можно изменить снова, правило удалить во вкладке «Правила разнесения».

## Разбор дубля

Вкладка «Дубли». Каждая пара это блок (`.card` вложенная: фон `--color-bg`, `--radius-lg`, отступы 14px, зазор 12px между блоками):

```
Похоже на дубль · одинаковая сумма 5 400 ₽, даты 6 сен, разные источники     ← причина от backend
┌───────────────────────────────────────────────────────────────────────────┐
│ Уже была в учёте                                                          │
│ 6 сен   Роял Канин 3 упаковки   Товары для перепродажи   Банк   −5 400 ₽  │
│                                                       [ Оставить эту ]     │
├───────────────────────────────────────────────────────────────────────────┤
│ Пришла повторно                                                           │
│ 6 сен   Корма Роял Канин, 3 уп. Товары для перепродажи   Бот    −5 400 ₽  │
│                                                       [ Оставить эту ]     │
└───────────────────────────────────────────────────────────────────────────┘
Вторая операция перестанет учитываться в остатке и отчётах. В истории она останется с пометкой «дубль».
                                                   [ Это не дубль, оставить обе ]
```

(Пример строки взят из v6; в MVP бота нет, источником будет «Ветменеджер» или «Вручную».)

- Верхняя операция это `duplicate_of` (первая попавшая в учёт), нижняя это сама помеченная (`status = duplicate`). Подписи «Уже была в учёте» / «Пришла повторно» ставит клиент по структуре ответа.
- Колонки внутри блока те же, что в «Все», с мелкими различиями: поле, по которому операции отличаются, не подсвечиваем (клиент не сравнивает).
- Причина дубля (строка над блоком) приходит текстом `duplicate_reason`; подпись по умолчанию «Похоже на дубль». Если причины нет, остаётся только подпись.
- «Оставить эту» (`secondary`, 36px / 44 на мобильном) вызывает `POST /v1/transactions/{id}/resolve-duplicate` с `keep_id` этой операции. Во время запроса обе кнопки блока отключены, подпись «Сохраняем…».
- «Это не дубль, оставить обе» (`text`) вызывает тот же эндпоинт с признаком «обе» (запрос к backend). Обе операции считаются, блок исчезает.
- После выбора: блок исчезает, тост «Оставили операцию от 6 сентября (Банк). Вторая не учитывается.» или «Обе операции остались в учёте.», счётчик вкладки уменьшается, остаток в шапке обновляется (запрос `['dashboard']` перезапрашивается).
- Подтверждения нет: действие понятное и подписано последствием под блоком. Откат на этапе 7.
- Блок не отвечает на вопрос, какая «правильнее»: предвыбора нет.

Пары идут по дате новых к старым. Тройки и более (три копии) на этапе 1 показываются как несколько пар с одной общей «первой» операцией (поведение backend, уточнение в handoff).

## Загрузка выписки

Диалог «Загрузка выписки» (раздел 9, ширина 540), открывается кнопкой «Загрузить выписку» (то же окно открывается из «Настройки → Подключения → Банк», `connections.md`). Файл: выгрузка из банка в формате 1С (`1CClientBankExchange`), файл `.txt`.

### Шаги

1. **Выбор.** Подзаголовок: «Выгрузите выписку из интернет-банка в формате 1С и выберите файл.» Поля:
   - «Счёт» (список банковских счетов `kind = bank`; если счёт один, выбран). Пояснение: «Для какого счёта эта выписка».
   - `FileDrop` (раздел 10).
   - Строка 12px `--color-ink-soft`: «Мы читаем суммы, даты и назначения платежей. Фамилии физических лиц не сохраняются.» Фраза верна только если backend действительно их отбрасывает (правило 6 из `CLAUDE.md`, запрос в handoff).
   - Кнопки: «Отмена», `primary` «Загрузить» (до выбора файла нажимается и даёт ошибку «Выберите файл выписки», как форма входа).
2. **Загрузка.** Поля заблокированы. `ProgressBar`: «Загружаем файл… 63%», затем неопределённый «Разбираем операции…». Закрыть диалог можно только кнопкой «Прервать» (отменяет запрос, ничего не сохраняется). Дольше 30 секунд под полосой: «Большой файл, подождите ещё немного.»
3. **Итог.**

```
Выписка загружена
Т-Банк · 7972 · операции с 1 августа по 9 сентября 2026

Загружено   148
Дублей        3
На проверку  12

Дубли и операции без статьи вы разберёте в соответствующих вкладках.
[ Показать на проверку ]  [ Показать дубли ]  [ Готово ]
```

Подпись «Загружено 148 · дублей 3 · на проверку 12» для скринридера читается одной фразой в `role="status"`. Три числа стоят вертикальным списком (подпись слева, число справа, 18px / 800); у чисел подсказок нет: каждое число это счётчик списка, который открывается кнопкой рядом (исключение описано в `components.md`, раздел 6). Определения: «загружено» это все новые операции, добавленные из файла, включая те, что ушли на проверку и в дубли; «дублей» это новые операции, похожие на уже существующие; «на проверку» это новые операции без статьи (договорённость с backend в handoff). Кнопки «Показать на проверку» и «Показать дубли» не показываются при нуле; они закрывают диалог и открывают вкладку. «Готово» (`primary`) закрывает диалог, список и итоги перезапрашиваются.

Повторная загрузка того же файла: сервер вернул, что новых операций нет. Итог: «Эти операции уже были загружены, новых нет. Ничего не добавлено и не задвоено.» Блок из трёх чисел не показывается, кнопка только «Готово».

Часть строк пропущена (backend вернул `skipped`): под итогом строка `--color-warn-ink`: «Не удалось прочитать 2 строки файла, они пропущены.» Подробности в журнале файла в MVP не показываем.

### Ошибки

| Ситуация | Где | Текст |
| --- | --- | --- |
| Файл не выбран | Под `FileDrop` | «Выберите файл выписки» |
| Расширение не `.txt` | Под `FileDrop` сразу после выбора | «Нужен файл в формате 1С с расширением .txt. В интернет-банке он называется «Выгрузка для 1С»» |

## Доступность

- Один `<h1>` «Транзакции». Заголовки блоков: «Итоги за сентябрь» (`<h2 class="sr-only">`), список под вкладками получает `aria-labelledby` на выбранную вкладку.
- Порядок Tab: слот действий, пагинация по месяцу, карточки итогов (каждая с подсказкой), вкладки (одна точка входа, стрелками внутри), содержимое вкладки, «Показать ещё».

- Контраст не ниже 4,5:1; приглушённая строка дубля `--color-ink-soft` на белом 5,2:1.
- Цели нажатия 44px на 820 и уже; 36–40px на широком экране (не меньше 24px по WCAG 2.2).
- Результаты действий объявляются: итог загрузки `role="status"`, ошибки `role="alert"`, тосты `aria-live`.
- Список и таблица при обновлении не перемещают фокус. После действия, удалившего строку, фокус на следующую строку; если её нет, на заголовок списка.
- `prefers-reduced-motion`: подъём карточек, анимации диалога и подсветки строки отключены.

## Критерии приёмки (для frontend и tester)

1. На 1280, 820 и 390px нет горизонтальной прокрутки и обрезанных чисел; ниже 1100px вместо таблицы список строк-карточек.
2. Итоги и баланс в шапке совпадают с моком и golden-набором; клиент ничего не суммирует. У каждой суммы и каждой карточки итога открывается подсказка с разбивкой.
3. Статья сохраняется из вкладок «На проверку» и «Все»; флажок «Создать правило» по умолчанию включён; сообщение о правиле и числе применений показано в диалоге (превью) и в тосте (итог).
4. Дубль разбирается одним действием; вторая операция в «Все» приглушена с плашкой «дубль».
5. Ручная операция: все проверки таблицы «Проверки и тексты ошибок» воспроизводятся; сумма уходит строкой, разобранной в копейки без `float`.
6. Загрузка выписки: выбор файла, прогресс, итог «Загружено N · дублей M · на проверку K», все ошибки таблицы. Повторная загрузка не задваивает.
7. Состояния загрузки, пусто (5 вариантов), ошибки, «данные устарели», «ошибка синхронизации» воспроизводятся на моках.
8. Нет слов «ИИ», «бот», «роль», «филиал» и красной кнопки «Удалить» у дубля.

# Экран «Подключения» (Настройки, этап 1)

Откуда приходят данные: Ветменеджер (по ключу API) и банк (на MVP только выписка 1С файлом). Функция 40. Источник внешнего вида: v6 `SET.vm`, `SET.bank` внутри `vSet` (внутреннее меню `.setnav`, карточка `.card` со строкой `.srow` и `.dot`, поля `.field` / `.inp`). Компоненты: `components.md` (4 Button, 5 Field, 9 Dialog, 10 FileDrop, 11 Toast, 12 Banner, 13 ConnectionStatus). Оболочка: `shell.md`.

Решения владельца: экраны из v6, нового не рисуем; ролей, бота и ИИ нет. Из v6 убраны: «Telegram-бот» (бота в MVP нет), «Пользователи» (ролей нет), «Автоотправка на почту» (в MVP банк это файл), «Частота синхронизации» как редактируемое поле (на MVP расписание фиксированное).

## Что отличается от v6 (не копировать)

| В v6 | Здесь | Причина |
| --- | --- | --- |
| Ключ показан как `••••••••••••4a7f` в поле-макете | Поле с замаскированным ключом отключено, кнопка «Заменить ключ». Целиком ключ не показывается и не возвращается API никогда | Безопасность. Показываются только последние 4 знака (`key_hint`) |
| «Приёмы, услуги, продажи, склад, врачи» | «Визиты, продажи и услуги» | Склад и врачи в данных этапа 1 не загружаются |
| Банк: «Автоотправка на почту», «Адрес для выписки», «Глубина истории» | «Загрузка файлом» и кнопка «Загрузить выписку» | Из задачи этапа: банк на MVP это выписка 1С файлом; API банка позже |
| Список банков «Т-Банк, Точка, Сбербанк…» | «Подойдёт выгрузка в формате 1С из любого банка» | Мы не обещаем прямую интеграцию |
| Зелёный статус «обновлено сегодня в 04:12» всегда | Шесть статусов (раздел 13 `components.md`) | Нужны ошибка, устаревание, синхронизация |
| Карточка «Работа без Ветменеджера» обещает закрытие смены | Текст без обещаний о смене | Экран закрытия смены не спроектирован |
| Внутреннее меню настроек сворачивается в столбик | Горизонтальная лента до 1100px | Меню в столбик занимало бы полэкрана на телефоне |

### Внутреннее меню

Источник: v6 `.setnav` (белая карточка, радиус 20, ширина 212px; кнопки 13,5px / 600; активная `--color-accent-faint` + `--color-accent-dark`). Группы и пункты v6 без «Пользователи» и «Telegram-бот»:

| Группа | Пункт | Статус на этапе 1 | Путь (ориентировочно) |
| --- | --- | --- | --- |
| Клиника | Основное | скоро | `/settings/main` |
| Клиника | Счета | скоро | `/settings/accounts` |
| Справочники | Категории | скоро | `/settings/categories` |
| Справочники | Направления | скоро | `/settings/directions` |
| Подключения | **Ветменеджер** | **готов** | `/settings/connections/vetmanager` |
| Подключения | **Банк** | **готов** | `/settings/connections/bank` |
| Прочее | Журнал действий | скоро | `/settings/log` |
| Прочее | Подписка | скоро | `/settings/billing` |

Заголовки групп: 11px, 700, капсом, `--color-ink-soft` (в v6 9,5px `--ink-faint`, не проходило по контрасту). Пункты «Скоро» по правилам оболочки: `disabled`, плашка `neutral` «Скоро» справа, не в порядке Tab. Открытие `/settings` ведёт на `/settings/connections/vetmanager`. Состояния пункта: обычное, наведение (фон `--color-bg`), фокус (`--focus-ring`), выбран (`aria-current="page"`), отключён («Скоро»). Высота пункта 40px (44px на 1100 и уже).

Вопрос владельцу: счета на этапе 1 заводит команда (решение этапа 0), но формы с выбором счёта (ручная операция, загрузка выписки) без экрана «Счета» работают только с уже существующими; нужно ли открыть «Счета» на этапе 1 (в контракте `GET|POST|PATCH /v1/accounts` отнесён к этапу 1). По умолчанию из этапа 0: счета заводит команда, пункт «Скоро».

На 1100px и уже внутреннее меню превращается в ленту над карточками: горизонтально прокручивается, пункты высотой 44px, без заголовков групп, порядок тот же (готовые первыми по порядку меню); выбранный пункт прокручивается в видимую область. Это переопределяет v6, где при `max-width: 1100px` меню становилось столбцом на всю ширину.

## Данные

| Запрос | Что |
| --- | --- |
| `GET /v1/connections` | Состояние всех подключений (запрос к backend: состав в `docs/handoff.md`) |
| `PUT /v1/connections/vetmanager` | Сохранить адрес и ключ. Тело: `address`, `key` (необязателен, если не заменяют) |
| `POST /v1/connections/{id}/sync` | Запустить синхронизацию (ответ 202 с `run`) |
| `POST /v1/imports/bank-statement` | Загрузка выписки (описана в `transactions.md`) |
| `GET /v1/accounts` | Счета для списка в диалоге выписки |

Пока идёт запуск синхронизации (`run.status = running`), экран опрашивает `GET /v1/connections` каждые 3 секунды, не дольше 10 минут. После завершения: тост, перезапрос `['transactions']`, `['dashboard']`.

Форма подключения Ветменеджера хранит значения только в состоянии формы. Ключ не пишется в журнал консоли, адрес страницы, `localStorage`, `sessionStorage` и не отправляется нигде, кроме `PUT`.

## Ветменеджер

### Блок «Ветменеджер» (карточка)

Верх: `ConnectionStatus` (раздел 13): точка + «Ветменеджер» + мета «визиты, продажи и услуги» + статус справа.

Ниже поля в виде v6 `.field` (подпись слева и поле справа в 200px; здесь поле гибкое, по `Field` из раздела 5; на 390 подпись над полем):

| Поле | Вид | Заметки |
| --- | --- | --- |
| Адрес системы | Текст, `inputmode="url"` | Пример в подсказке: «Например, aibolit.vetmanager.ru». Клиент обрезает пробелы, убирает `https://` и завершающий `/` перед отправкой; больше ничего не правит |
| Ключ доступа | Пароль-поле | См. «Ключ» ниже |
| Обновление | Обычный текст, не поле | «Каждую ночь в 04:00» (в v6 это поле; на MVP расписание не настраивается). Время приходит от backend (`schedule`), в часовом поясе клиники |

Кнопки внизу карточки: `primary` «Сохранить» (при подключённой системе) или «Подключить» (если не подключена); справа `secondary` «Синхронизировать» (только когда подключено). На 390 друг под другом, «Сохранить» сверху.

Сноска под кнопками (12,5px, `--color-ink-soft`, как `.note`): «Ключ выдаётся в настройках Ветменеджера, раздел «Интеграции». Мы только читаем данные и ничего в них не меняем. Фамилии владельцев животных не сохраняются.» Последнее предложение верно только если так сделает backend (правило 6 из `CLAUDE.md`, запрос в handoff).

### Ключ

| Состояние | Вид |
| --- | --- |
| Не подключено | Пустое пароль-поле, подпись «Ключ доступа», подсказка «Вставьте ключ из Ветменеджера» |
| Подключено | Поле отключено, значение «••••••••••••4a7f» (маска + `key_hint`, последние 4 знака), рядом `secondary` «Заменить ключ» |
| Замена | Поле очищено и включено, фокус в нём, вместо «Заменить ключ» кнопка `text` «Не менять». Если ключ не введён, при сохранении он остаётся прежним |
| После сохранения | Опять маска с новым `key_hint`; введённое значение стирается из формы |
| Ошибка | Под полем, как у любого поля (раздел 5) |

Показать ключ целиком кнопкой нельзя ни до, ни после сохранения. Если ключ потерян, его берут заново в Ветменеджере и заменяют. Маска и 4 знака читаются скринридером как «Ключ скрыт, последние четыре знака 4 а 7 эф» (достаточно текста `aria-label` на поле).

### Проверки и тексты ошибок

| Поле | Условие | Текст |
| --- | --- | --- |
| Адрес | пусто | «Введите адрес вашего Ветменеджера» |
| Адрес | не похож на адрес (нет точки, пробелы внутри, запрещённые символы) | «Адрес выглядит неверно. Пример: aibolit.vetmanager.ru» |
| Ключ | пусто при подключении | «Вставьте ключ из Ветменеджера» |
| Адрес, сервер | `validation`, адрес недоступен | «Не удалось связаться с aibolit.vetmanager.ru. Проверьте адрес» (имя адреса подставляется из поля) |
| Ключ, сервер | `validation`, ключ не принят | «Ветменеджер не принял ключ. Проверьте ключ и адрес» |
| Общая | нет связи с нашим сервером | «Нет связи с сервером. Проверьте интернет и повторите» |
| Общая | сбой | «Не получилось сохранить подключение. Попробуйте ещё раз» |

Проверка ключа делается сервером при сохранении (запрос к backend: `PUT` возвращает ошибку `validation` с кодом причины, если ключ не принят или адрес недоступен). Пока идёт проверка, у кнопки «Сохраняем…».

После успешного сохранения: тост «Ветменеджер подключён. Начали загружать данные, это может занять несколько минут.» Статус переходит в «синхронизация идёт». При смене адреса или ключа у уже подключённой системы: «Подключение сохранено.»

### Синхронизация

Кнопка «Синхронизировать» (`secondary`). Во время запуска: «Синхронизируем…», отключена; статус «синхронизация идёт…». Закончилась: тост по результату.

| Результат запуска | Тост | Статус после |
| --- | --- | --- |
| `success` | «Ветменеджер обновлён: загружено 24 операции.» (число из `counts.value`, склонение клиентом) | «обновлено сегодня в 04:12» |
| `success`, ничего нового | «Ветменеджер обновлён. Новых операций нет.» | то же |
| `partial` | «Ветменеджер обновлён не полностью. Подробности в списке запусков ниже.» | «обновлено не всё» + плашка `warning` |
| `failed` | «Не получилось обновить Ветменеджер: <причина>.» | «не удалось обновить» + плашка `danger` |
| Запрос на старт не прошёл (сеть) | «Не получилось запустить синхронизацию. Проверьте интернет и повторите.» | без изменений |
| `conflict`: уже идёт | «Синхронизация уже идёт. Подождите, пока закончится.» | «синхронизация идёт…» |
| 429 (слишком часто) | «Синхронизировать можно не чаще раза в 5 минут. Попробуйте позже.» (период подтвердить у backend) | без изменений |

Опрос дольше 10 минут: статус остаётся «синхронизация идёт…» и добавляется строка «Идёт дольше обычного. Обновите страницу чуть позже.» Первая синхронизация (истории ещё нет) пишет в статусе «загружаем историю…».

### Коды ошибок синхронизации (`run.error_code`)

Текст `error.message` backend не показываем. Полная фраза идёт в блок статуса и в тост, краткая в полосу на экране «Транзакции» (`transactions.md`).

| Код (запрос к backend) | Полная фраза | Краткая |
| --- | --- | --- |
| `invalid_key` | «Ветменеджер не принял ключ. Проверьте ключ в настройках Ветменеджера, раздел «Интеграции», и замените его здесь» | «ключ не подошёл» |
| `unreachable` | «Ветменеджер не отвечает. Попробуем снова по расписанию или нажмите «Синхронизировать»» | «Ветменеджер не отвечает» |
| `rate_limited` | «Ветменеджер просит подождать. Попробуйте через несколько минут» | «Ветменеджер просит подождать» |
| `unknown` и всё остальное | «Не получилось обновить данные. Это сбой на нашей стороне, ваши данные не пострадали. Попробуйте ещё раз» | «сбой при обновлении» |

При `invalid_key` рядом с полным текстом кнопка `secondary` «Заменить ключ» (запускает режим замены). Данные, загруженные раньше, остаются на месте и продолжают считаться: в тексте всегда «Показаны данные на <дата, время последнего успеха>».

### Последние запуски (`sync_runs`)

Белая карточка с заголовком «Последние запуски» (v6 `.klabel`, 11px капсом `--color-ink-soft`). Таблица, 5 последних запусков, новые сверху:

| Колонка | Поле | Вид |
| --- | --- | --- |
| Когда | `started_at` | «9 сентября, 04:12» (время в поясе клиники). Для сегодняшнего «сегодня, 04:12» |
| Результат | `status` | Плашка: `running` «идёт» (`neutral`), `success` «успешно» (`success`), `partial` «частично» (`warning`), `failed` «ошибка» (`danger`) + для ошибки под плашкой краткая причина из таблицы кодов |
| Загружено | `counts` (`Figure`, `unit = count`) | Число с `FigureTip` (раздел 2). Разбивка: «Новых операций», «Обновлено», «Пропущено как дубли» (все строки приходят от backend). Если запуск не загрузил ничего, «0» с подсказкой, если `Figure` пришла, и «—» без подсказки, если запуск упал до загрузки |

До 1100px строка превращается в карточку: слева «9 сентября, 04:12» и плашка, справа число. Пусто (запусков не было): строка 13,5px `--color-ink-soft` «Запусков пока не было. Они появятся после подключения.» Загрузка: три строки-заглушки. Ошибка загрузки: «Не получилось загрузить список запусков.» и кнопка `text` «Повторить». Таблица доступна: `<caption class="sr-only">Последние запуски синхронизации Ветменеджера</caption>`.

Это единственное место, где счётчик операций получает подсказку из `Figure`, а не списком под ним (операции запуска не фильтруются отдельно).

## Банк

Карточка: `ConnectionStatus`: название «Банк», мета «выписка 1С, загрузка файлом», статус справа:

| Условие | Статус |
| --- | --- |
| Выписок ещё не было | «выписок ещё не было» (серая точка) |
| Есть выписка | «последняя выписка по 9 сентября» (зелёная точка) |
| Выписка давно не загружалась (`data_stale`) | «последняя выписка по 28 августа» (жёлтая точка) + плашка `warning` «данные устарели» |

Список счетов (v6 `.srow`): по строке на банковский счёт: слева название «Т-Банк · 7972» и мета «выписка по 9 сентября» (или «выписок ещё не было»), справа ничего (кнопка у блока). Данные: `GET /v1/connections` → `bank.accounts[]` (запрос к backend). Если банковских счетов нет: «Нет банковских счетов. Счёт пока заводит команда ВетФинанс.» и кнопки загрузки нет.

Кнопка `primary` «Загрузить выписку» открывает диалог «Загрузка выписки» (`transactions.md`) с предвыбранным счётом, если строка выбрана через кнопку `secondary` «Загрузить» в строке счёта. После успешной загрузки в карточке обновляется дата последней выписки.

Сноска (`.note`): «Подойдёт выгрузка в формате 1С из любого банка. Подключение банка напрямую появится позже.» «Появится позже» без дат: обещаний нет.

Полей настройки у банка нет (в v6 они были для автоотправки). `PUT /v1/connections/bank` на этапе 1 интерфейсом не используется (вопрос backend в handoff).

Состояния: загрузка и ошибка как у Ветменеджера; пусто: нет счетов, см. выше.

## Доступность

- Один `<h1>` «Настройки»; заголовок раздела `<h2>` («Ветменеджер», «Банк»), `aria-labelledby` для карточки.
- Внутреннее меню `<nav aria-label="Разделы настроек">`, выбранный пункт `aria-current="page"`.
- Статус синхронизации текстом, смена объявляется (`aria-live="polite"` на тексте статуса); ошибка `role="alert"`.
- Цвет точки не единственный носитель: рядом слово и, где нужно, плашка.
- Поля с подписями, ошибки связаны через `aria-describedby`; фокус на первое поле с ошибкой.
- Ключ: `autocomplete="off"`, не попадает в историю и автозаполнение; маска не содержит ключа в разметке (в DOM только `••••` и `key_hint`).
- Цели нажатия не меньше 44px на 820 и уже.

## Критерии приёмки

1. Ключ после сохранения не виден нигде: ни в поле, ни в DOM, ни в ответах API, ни в `localStorage`; видны только последние 4 знака.
2. Подключение, замена ключа, ошибка ключа, ошибка адреса воспроизводятся на моках.
3. «Синхронизировать» проходит весь цикл (идёт, успешно, частично, ошибка); для каждого результата свой текст.
4. Таблица запусков показывает число с подсказкой-разбивкой.
5. Банк: диалог загрузки открывается отсюда и обновляет «последнюю выписку».
6. Нет пунктов «Telegram-бот», «Пользователи», слов «роль», «бот», «ИИ». Остальные пункты настроек «Скоро» и не нажимаются.
7. На 1280, 820, 390 нет горизонтальной прокрутки страницы.

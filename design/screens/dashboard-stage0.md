# Рабочий стол, этап 0

> С этапа 2 действует `design/screens/dashboard.md`. Этот файл остаётся как история этапа 0. Различие для frontend: акцентная карточка «Остаток на счетах» стала большим блоком баланса (`BalanceHero`), а акцентная карточка теперь «Хватит на N дней».

На этапе 0 экран отвечает на один вопрос: «сколько денег на счетах». Две карточки показателя с подсказками. Остальное из прототипа v6 (`vDash`) появится на этапе 2 и пока не показывается. Компоненты: `KpiCard`, `FigureTip`, `Pill` из `design/components.md`. Оболочка: `design/screens/shell.md`.

Gate этапа 0 (из `docs/stages.md`): пользователь входит, видит остаток; число совпадает с golden-тестом; подсказка раскрывает разбивку по счетам.

## Структура

```
Рабочий стол
9 сентября 2026 · данные обновлены в 04:12

┌───────────────────────────┐  ┌───────────────────────────┐
│ 💰  ОСТАТОК НА СЧЕТАХ      │  │ 💳  В БАНКЕ                │
│     412 800 ₽              │  │     341 300 ₽              │
└───────────────────────────┘  └───────────────────────────┘

Наведите или нажмите на сумму: покажем, из чего она состоит.
```

Цифры выше взяты из примера v6 (341 300 + 71 500 = 412 800) и годятся как мок-данные; реальные числа приходят от API.

## Данные

Один запрос: `GET /v1/dashboard` (на этапе 0 в ответе только `balance.total` и `balance.bank`, плюс `as_of` и `data_as_of`; уточнение для backend в `docs/handoff.md`). Запрос выполняется TanStack Query с ключом `['dashboard']`.

| Место на экране | Поле API | Как показывается |
| --- | --- | --- |
| Заголовок | | «Рабочий стол» |
| Пояснение, дата | `as_of` | «9 сентября 2026» (формат `Intl` `ru-RU`, `day: numeric, month: long, year: numeric`) |
| Пояснение, время | `data_as_of` | «данные обновлены в 04:12» — время в поясе клиники (`clinic.timezone`). Если `data_as_of` пуст: «данные ещё не загружались» |
| Карточка 1 «Остаток на счетах», число | `balance.total.value`, `.unit` | Формат по `components.md`, рубли |
| Карточка 1, подсказка | `balance.total.breakdown` (по счетам), `.note`, `.source` | `FigureTip`, заголовок «Остаток на счетах». Строки разбивки это счета: расчётный счёт, касса клиники и т. д. |
| Карточка 2 «В банке», число | `balance.bank.value` | Формат по `components.md` |
| Карточка 2, подсказка | `balance.bank.breakdown`, `.note`, `.source` | `FigureTip`, заголовок «В банке» |

Клиент ничего не суммирует: «В банке» и «Остаток на счетах» приходят готовыми, разность или долю между ними не показываем.

## Состояния

### Загрузка (первый запрос, данных нет)

- Шапка: заголовок виден, пояснение заглушкой 220×13px (`--color-track`, пульс).
- Две карточки в состоянии «Загрузка» из `components.md` (подпись и число блоками), высота 88px. Подсказки не открываются.
- Контейнер `aria-busy="true"`, скрытый текст «Загружаем остаток».
- Если загрузка дольше 8 секунд, под карточками строка 13px `--color-ink-soft`: «Загрузка идёт дольше обычного. Подождите ещё немного.»
- Повторный заход на экран с кэшем: сразу показываем прежние цифры, запрос идёт в фоне без заглушек (TanStack Query `isLoading`, а не `isFetching`).

### Ошибка

Если весь запрос не удался, вместо двух карточек одна карточка на всю ширину (белая, `--card-padding`, слева рамка 3px `--color-bad`, как у `.tip-card.wr` в v6, но цвет `--color-bad`):

- Плашка `danger` «не загрузилось».
- Заголовок 16px, 700: «Не получилось загрузить остаток».
- Текст 13,5px, `--color-ink-soft`: «Это сбой на нашей стороне, ваши данные не пострадали. Попробуйте ещё раз.»
- Кнопка «Повторить» (`.act`, обычная, высота 40px; 44px на 390px). Во время повторной загрузки кнопка неактивна, текст «Загружаем…». Блок `role="alert"` при появлении.

По коду ошибки:

| Ответ | Что показываем |
| --- | --- |
| Нет сети или таймаут | Текст «Нет связи с сервером. Проверьте интернет и повторите.», кнопка «Повторить» |
| `unauthorized` | Не показываем карточку: переход на экран входа с сообщением «Сессия закончилась. Войдите снова.» |
| `forbidden`, `not_found` | Экран «Ваша почта пока не привязана к клинике» из `shell.md` |
| `sync_failed`, 5xx | Текст по умолчанию выше |

Текст `error.message` от backend не показываем напрямую. Если при повторном запросе (фоновом обновлении) пришла ошибка, а данные уже есть, цифры остаются на месте, а над карточками появляется строка `warning`: плашка «не удалось обновить» и текст «Показаны данные на 04:12» (время из `data_as_of`), справа ссылка-кнопка «Обновить».

### Нет счетов

Условие: в `balance.total.breakdown` нет ни одной строки (договорённость с backend в `docs/handoff.md`; признак «нет счетов» не выводим из нулевого остатка: клиника со счётом и нулём на нём это обычное состояние «0 ₽»).

Вместо двух карточек одна белая карточка на всю ширину: значок 💳 (29px), заголовок 16px, 700 «Счетов пока нет», текст 13,5px `--color-ink-soft`: «Остаток появится, когда в сервисе будет хотя бы один счёт или касса.» Подсказки и числа нет. Кнопки «Добавить счёт» на этапе 0 нет, потому что экрана настроек ещё нет (на этапе 0 счета заводит команда; вопрос в `docs/handoff.md`). С открытием настроек (этап 1) в карточку добавляется кнопка «Добавить счёт» (`.act.pri`) со ссылкой в Настройки → Счета.

### Нулевой остаток

Счета есть, остаток 0: показываем «0 ₽», подсказка открывается (в разбивке счета с нулями), подстрока «на счетах пусто». Это не ошибка и не «пусто».

### Отрицательный остаток

Число с минусом «−12 300 ₽», подстрока «ниже нуля» (цвет `--color-bad`, на акцентной карточке белая), подсказка работает. Языком, не пугающим: «ниже нуля», а не «долг» или «катастрофа».

### Данные устарели

На этапе 0 не включается: синхронизации с Ветменеджером и банком ещё нет, `data_as_of` на тестовых данных ничего не значит, и клиент порог не считает. Макет на будущее (этап 1): если backend отдаст признак устаревания (запрос в `docs/handoff.md`), в пояснении шапки рядом с временем показывается плашка `warning` «данные устарели» и текст «Последнее обновление: вчера в 04:12. Проверьте подключения»; цифры остаются на месте и открывают подсказки как обычно.

## Подсказки на карточках

Открываются по наведению, фокусу и тапу (`components.md`, `FigureTip`). Примерное содержимое для проверки макета (из v6 `acc_all`, без блока «Неделю назад» и «Хватит на 11 дней»: это поля этапа 2):

```
[Остаток на счетах]
💰 412 800 ₽
Расчётный счёт        341 300 ₽
Касса клиники          71 500 ₽
─────────────────────────────
<Figure.note>
Источник: [Банк] [Внесено вручную]
```

Сноска под карточками: «Наведите или нажмите на сумму: покажем, из чего она состоит.» Одна строка на 1280, две на 390.

## Доступность

- Заголовок страницы `<h1>Рабочий стол</h1>`; карточки в списке (`<ul>`, по одной в `<li>`) или в области `role="group"` с `aria-label="Остаток на счетах"`.
- Обе карточки доступны с клавиатуры, порядок Tab: «Остаток на счетах», «В банке». Подсказка открывается по фокусу, `Esc` закрывает.
- Смысл не только цветом: отрицательное число с минусом и подписью «ниже нуля», ошибка с плашкой и текстом.
- Анимация появления экрана и подъём карточки отключаются при `prefers-reduced-motion`.
- Контраст всех текстов не ниже 4,5:1. Цели нажатия карточек и кнопок не меньше 40px.

## Критерии приёмки (для frontend и tester)

1. На 1280, 820 и 390px нет горизонтальной прокрутки и обрезанных чисел.
2. `balance.total` и `balance.bank` на экране совпадают с моком и golden-набором; клиент их не пересчитывает.
3. Подсказка каждой карточки показывает строки `breakdown`, `note` и `source` из ответа и открывается наведением, фокусом и тапом; `Esc` закрывает.
4. Состояния загрузки, ошибки (с кнопкой «Повторить»), «нет счетов» и «0 ₽» воспроизводятся на моках.
5. На экране нет частей из таблицы «позже», нет слов «ИИ», «роль», «филиал».

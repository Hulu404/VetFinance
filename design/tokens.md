# Токены VetFinance

Файл с переменными: `design/tokens.css`. Источник значений: `:root` и литералы в стилях `design/vetfinance-prototip-v6.html` (v6). Тёмной темы в MVP нет. Frontend берёт цвета, размеры и анимации только из этих переменных, числа и hex-коды в компонентах не пишет.

## Подключение

```ts
// frontend/src/main.tsx
import './styles/tokens.css'   // копия или импорт design/tokens.css; источник правды остаётся в design/
```

Значки меню лежат в `design/icons.svg` (спрайт). Вставить один раз в разметку, использовать как `<svg class="icon" aria-hidden="true"><use href="#ic-home"/></svg>`.

## Шрифт Onest

Прототип грузит Onest с Google Fonts. В продукте так не делаем: запрос к чужому серверу передаёт адрес посетителя за рубеж (хостинг в РФ отложен, но 152-ФЗ учитываем с самого начала), а шрифт может не загрузиться. Подключаем из пакета, он отдаётся с нашего же домена.

```bash
npm i @fontsource/onest
```

```ts
// frontend/src/fonts.ts — нужны кириллица и латиница, веса 400, 500, 600, 700, 800
import '@fontsource/onest/cyrillic-400.css'
import '@fontsource/onest/cyrillic-500.css'
import '@fontsource/onest/cyrillic-600.css'
import '@fontsource/onest/cyrillic-700.css'
import '@fontsource/onest/cyrillic-800.css'
import '@fontsource/onest/latin-400.css'
import '@fontsource/onest/latin-500.css'
import '@fontsource/onest/latin-600.css'
import '@fontsource/onest/latin-700.css'
import '@fontsource/onest/latin-800.css'
```

- Знак рубля ₽ и минус − (U+2212) входят в кириллический набор; если ₽ вдруг рисуется запасным шрифтом, добавить `@fontsource/onest/symbols-600.css`.
- Пакет ставит `font-display: swap`. Предзагружать (`<link rel="preload">`) только `cyrillic-600` и `cyrillic-800` (основной текст и числа).
- Запасной стек в `--font-sans`: `ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, Arial, sans-serif`.

### Этап 1: диалог, тост, загрузка файла

Новых цветов нет, только слои и размеры. Затемнение сделано из цвета меню, тень диалога это `--shadow-tip`, радиус `--radius-card`.

| Токен | Значение | Где |
| --- | --- | --- |
| `--color-backdrop` | `rgba(21,19,28,.5)` | Затемнение страницы под диалогом |
| `--z-dialog`, `--z-toast` | 90, 100 | Диалог ниже подсказки (99), тост выше всех |
| `--dialog-width`, `--dialog-width-wide` | 480px, 540px | Диалог с формой; диалог загрузки выписки |
| `--toast-width` | 380px | Тост на экранах шире 820px |
| `--color-drop-border` | `--color-control-border` | Пунктирная рамка поля загрузки файла |
| `--progress-height` | 10px | Полоса прогресса (в v6 `.track`) |

Граница адаптива 1100px, которую этап 0 отложил, возвращается: на экранах 821–1100px область содержимого уже 500–770px, и таблица операций в ней не помещается. Ниже 1100px таблица операций превращается в список строк-карточек (`screens/transactions.md`), а внутреннее меню настроек в горизонтальную ленту.

### Границы адаптива

В CSS пишутся числами (переменные в медиазапросах не работают).

| Граница | Что меняется |
| --- | --- |
| больше 820px | Боковое меню слева, 252px |
| до 820px включительно | Меню становится верхней панелью, отступы страницы 18px 14px |
| до 720px включительно | Ряд из трёх карточек показателей (Рабочий стол) в одну колонку; от 721px три колонки |
| до 560px | Ряд из двух карточек показателей в одну колонку |
| 1280px | Целевая ширина десктопа. Область содержимого не шире 1280px (вместе с отступами), прижата к меню, как в v6; на более широких экранах справа пустое поле |

Целевые ширины проверки: 1280, 820, 390 px. Граница 1100px из v6 (сетки в одну колонку) для этапа 0 не нужна: на экранах 821–1100px карточки остаются в две колонки. Вернётся с экранами, где есть три и более колонок.

## Что изменено по сравнению с v6 и почему

| Что | Было в v6 | Стало | Причина |
| --- | --- | --- | --- |
| Текст `--color-ink-faint` | Подписи, мета и сноски цветом `#A7A5B2` | Для текста берём `--color-ink-soft`; `faint` только для значков и отключённого | Контраст 2,4:1 на белом, нужно не меньше 4,5:1 |
| Размеры мелкого текста | 9,5 / 10 / 10,5 / 11,5 / 12,5 px | Шкала 11 / 12 / 13 | 9,5–10 px не читается на мобильном; 15 значений схлопнуты в 11 |
| Текст на `-soft` фоне | `ok` на `ok-soft` 4,0:1; `warn` на `warn-soft` 4,0:1; `vm` на `vm-soft` 4,4:1 | Добавлены `--color-ok-ink`, `--color-warn-ink`, `--color-vm-ink` | Плашки 11 px должны давать 4,5:1 |
| Подпись на акцентной карточке | Белый 72% (3,9:1) | Белый 85% (4,9:1) | Контраст |
| Рамка поля ввода | `#EDEAF2` | `--color-control-border` `#8E8C9A` | Граница поля должна быть заметна (3:1, WCAG 1.4.11). В v6 поле было только макетом |
| Рамка фокуса | `border-radius: 8px` всем элементам | Радиус элемента не меняется; на тёмном белая рамка | Рамка с чужим радиусом ломает форму карточки; бордовый на `#15131C` почти не виден |
| Радиусы | 6, 7, 10, 11, 12, 13, 14, 15, 20 | 7, 10, 12, 14, 20 | Схлопнуты близкие значения (11→12, 13→14, 15→14) |
| Время переходов | .14 / .16 / .18 / .25 / .28 s | .15 / .18 / .28 s | То же |
| Шрифт | Google Fonts | Пакет `@fontsource/onest` | См. раздел «Шрифт» |

Остальные значения (цвета бренда, смысла, тени, градиент, размеры 252 и 1280) перенесены без изменений. Все правки цвета кроме новых токенов `-ink` и `control-border` дают разницу, незаметную глазу; их стоит показать партнёру (см. `docs/handoff.md`).

# Этапы MVP

Один этап — один законченный модуль: backend и frontend вместе, с рабочим экраном. Сначала тонкий сквозной срез (этап 0), дальше по боли владельца: «где деньги» → «заработали ли» → прогноз.

Правила для всех этапов:

- Designer и tester идут на шаг впереди: спецификации экранов и эталонные данные этапа N готовы до начала разработки этапа N.
- Backend публикует заглушки эндпоинтов этапа в `docs/api-contract.md` и `backend/openapi.json` в первые дни этапа. Frontend работает на mock-сервере из контракта и переключается на реальный API, когда эндпоинт готов.
- Расчёт без golden-теста в `tests/golden/` не считается готовым.
- Этап закрывается, только когда выполнен gate. Незакрытый баг уровня blocker или major в `docs/bugs.md` не даёт закрыть этап.
- Недели ориентировочные, для одного разработчика с Claude Code.
- Пилотной клиники пока нет: этапы 0–6 проверяются на синтетических эталонных данных tester и на тестовом аккаунте Ветменеджера, если он будет. Реальная клиника нужна не позже конца этапа 3.
- Дизайн делает партнёр владельца продукта. Агент `designer` не придумывает внешний вид: переводит материалы партнёра и прототип v6 в токены, компоненты и спецификации экранов и проверяет вёрстку. Спорные решения по внешнему виду уходят партнёру через владельца продукта.
- Хостинг в РФ отложен: Supabase и Railway. Данные владельцев животных не загружаем.

## Этап 0. Скелет · неделя 1

**Модуль:** вход, клиника, деплой и один сквозной показатель «остаток на счетах» от данных до экрана.

| Роль | Что делает |
| --- | --- |
| backend | схема `clinics`, `memberships`, `accounts`, `transactions` с RLS; вход по Supabase JWT; `engine/money.py` и расчёт остатка; `GET /v1/clinic`, `GET /v1/accounts`, `GET /v1/dashboard` (только `balance.total`, `balance.bank`); деплой на Railway |
| frontend | каркас (Vite, роутер, TanStack Query), `tokens.css`, mock-сервер из контракта, экран входа, оболочка с меню, Рабочий стол с одной карточкой остатка и подсказкой `FigureTip` |
| designer | `tokens.css`, `tokens.md`, первые компоненты (карточка показателя, `FigureTip`, плашка), спецификация оболочки и Рабочего стола |
| tester | эталонный набор данных №1 (счета и операции), golden-тест остатка, smoke-сценарий e2e «вход → остаток» |

**Gate:** пользователь входит, видит остаток на тестовых данных; число совпадает с golden-тестом; подсказка раскрывает разбивку по счетам; деплой работает; RLS не отдаёт данные чужой клиники (тест).

## Этап 1. Данные и Транзакции · недели 2–3

**Модуль:** загрузка данных и экран «Транзакции». Функции 6–10, 36–38.

| Роль | Что делает |
| --- | --- |
| backend | загрузчик Ветменеджера (визиты, продажи, услуги), импорт выписки 1С, ручной ввод, хеш и разбор дублей, категории и правила разнесения, `sync_runs`; воркер по расписанию; эндпоинты раздела «Транзакции» и подключений |
| frontend | экран «Транзакции» (вкладки «Все», «На проверку», «Дубли»), правка статьи с созданием правила, ручная операция, загрузка выписки, экран подключений, состояния «данные устарели» и «ошибка синхронизации» |
| designer | спецификации «Транзакции», «Подключения», состояния загрузки, пусто, ошибка; тексты |
| tester | эталон №2: выписка 1С с дублями и непонятными операциями, выгрузка Ветменеджера; golden на дубли и правила; e2e «загрузить выписку → разнести → увидеть в списке» |

**Gate:** на реальной или близкой к реальной выписке дубли находятся без ложных срабатываний; правило разнесения применяется к новым операциям; повторная загрузка того же файла ничего не удваивает; ФИО владельцев животных не попадают в БД.

## Этап 2. Рабочий стол · недели 4–5

**Модуль:** ответ на вопрос «где деньги». Функции 1–5.

| Роль | Что делает |
| --- | --- |
| backend | движок: остаток, «хватит на N дней», доходы и расходы месяца, динамика остатка; советы по правилам с блоком «Почему?» из результата движка (шаблоны); полный `GET /v1/dashboard` |
| frontend | Рабочий стол целиком: карточки, график, советы с раскрытием «Почему?», подсказки на каждой цифре |
| designer | финальная спецификация Рабочего стола, прототип v7 (исправленные цифры, без ролей и филиалов) |
| tester | эталон №3 (месяц с известными итогами); golden остатков, «хватит на N дней», советов; проверка, что каждая цифра на экране имеет подсказку |

**Gate:** цифры Рабочего стола совпадают с golden до копейки; у каждой цифры есть разбивка и источник; на тестовых данных появляется как минимум один совет с понятным «Почему?».

## Этап 4. Платёжный календарь и Обязательства · недели 8–9

**Модуль:** «хватит ли денег впереди». Функции 21–23.

| Роль | Что делает |
| --- | --- |
| backend | вычисление регулярных платежей из истории банка, обязательства (кредиты, лизинг, оборудование), календарь на 22 дня, оповещения о кассовом разрыве с предложением переноса (перебор в пределах допустимой отсрочки) |

| designer | спецификации календаря и обязательств, состояние «красный день» с подписью, не только цветом |
| tester | эталон №5: известные платежи и выручка по дням недели; golden остатка по дням; сценарий «разрыв → предложение → разрыв закрыт» |

**Gate:** остаток по каждому дню совпадает с golden; предложенный перенос действительно закрывает разрыв; обязательства попадают и в календарь, и в строку ОПиУ этапа 3.

## Этап 6. Финмодель · недели 12–13

**Модуль:** прогноз на 4 квартала. Функции 24–29 и 31 (30 и 32 позже).

| Роль | Что делает |
| --- | --- |
| backend | прогноз (тренд × сезонный индекс, правила при истории меньше 24 и 12 месяцев), три сценария, допущения с пересчётом, библиотека рычагов в коде, план-факт с отклонением по рычагам, комментарии по шаблону |
| frontend | экран «Прогноз» с переключателем сценариев, таблица кварталов, экран допущений, рычаги, план-факт |
| designer | спецификации прогноза и допущений, пометка «низкая точность» |
| tester | эталон №7: история на 24+ месяца и на 14 месяцев; golden прогноза по кварталам во всех трёх сценариях; проверка, что рост считается к предыдущему кварталу |

**Gate:** прибыль каждого квартала равна тождеству по строкам таблицы; рост к предыдущему кварталу; при короткой истории показывается пометка о точности; изменение допущения пересчитывает прогноз одинаково на экране и в golden.

## Этап 7. Запуск · неделя 14

**Модуль:** подписка, журнал, админка, пилот. Функции 40, 41, 50–52.

| Роль | Что делает |
| --- | --- |
| backend | биллинг через ЮКассу (10 000 ₽ подключение, 3 500 ₽ в месяц, первый месяц бесплатно), журнал действий с откатом 7 дней и хранением 90 дней, админка основателя |
| frontend | экран «Подписка», журнал с кнопкой отката, админка основателя |
| designer | спецификации, финальное дизайн-ревью всей вёрстки против v7 |
| tester | регрессия по всем эталонным наборам, e2e по полному пути клиента, нагрузочная проверка синхронизации |

**Gate:** клиника проходит путь «регистрация → подключение → оплата → отчёты»; откат ручной правки работает; пилотная клиника пользуется неделю без blocker-багов; перед подключением первой реальной клиники закрыт вопрос хостинга и 152-ФЗ (до этого момента хостинг в РФ отложен).

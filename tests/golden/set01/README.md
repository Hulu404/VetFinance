# Эталонный набор №1: остатки на счетах

Две выдуманные клиники для проверки расчёта остатка и изоляции клиник.

## Файлы

- `data.json` — входные данные (сид для БД и вход для движка). Собран `tools/gen_set01.py` (детерминированно), в git лежит готовый файл.
- `expected.json` — ожидаемые остатки. Считает `tools/compute_expected_set01.py` независимо от кода продукта (чистый Python, целые копейки, без импорта из `backend/`). Пересчёт: `python tests/golden/tools/compute_expected_set01.py`.

## Формат data.json

```
{ "as_of_cases": ["2026-08-31", "2026-09-09", "2026-09-30"],
  "clinics":      [{ id, name, timezone, safe_balance }],
  "accounts":     [{ id, clinic_id, name, type: "bank"|"cash", opening_balance, opening_date }],
  "transactions": [{ id, clinic_id, account_id, date, description, category|null,
                     source: bank|vetmanager|bot|manual, kind: in|out|transfer,
                     amount, status: ok|check|duplicate, transfer_group? }] }
```

- Деньги: целые копейки. `amount` со знаком: поступление `> 0`, расход `< 0`, у `transfer` знак по направлению для данного счёта.
- Перевод между своими счетами = две проводки (`kind: transfer`, общий `transfer_group`), суммы противоположны, итог по клинике не меняется.
- `id` строковые (`A-bank`, `A-tx-001`); при загрузке в БД с uuid backend делает отображение сам, сверка идёт по названиям счетов (`breakdown.label`).
- `transfer_group` и `type`/`opening_*` у счёта в контракте не описаны: предложение, см. `docs/handoff.md`.

## Состав

- Клиника A: расчётный счёт, резервный счёт, касса; 57 операций 2026-08-01..2026-09-15: выручка, расходы, 4 перевода, 2 дубля (`status: duplicate`), 1 операция `check`, операция ровно на дату as_of и операции после неё.
- Клиника B: расчётный счёт и касса; 16 операций, 1 перевод, 1 дубль, 1 операция после as_of.

## Правило остатка (решение тестировщика)

`остаток(счёт, as_of) = opening_balance + сумма amount операций этого счёта, где opening_date <= date <= as_of и status != duplicate`.

1. Операция в день `as_of` входит (конец дня). Операции позже `as_of` не входят.
2. `status = duplicate` не входит (деньги уже учтены в оригинале).
3. `status = check` (категория не определена) входит: деньги реально ушли, статья неважна для остатка.
4. Переводы входят обычными проводками.
5. `opening_balance` — остаток на начало дня `opening_date`; операции этого дня входят.
6. `balance.total` = сумма всех счетов; `balance.bank` = сумма счетов `type=bank`; `balance.cash` = `type=cash`.
7. Figure: `breakdown` по одной строке на счёт (`label` = название счёта); для `bank` только расчётные счета. `source` (решение владельца продукта) = объединение `source` операций, вошедших в сумму этой Figure, без повторов, в порядке bank, vetmanager, bot, manual; операций нет -> `["manual"]`. Ожидаемые значения лежат в `expected.json`.

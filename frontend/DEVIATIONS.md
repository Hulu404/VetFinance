# Отклонения от прототипа v6 и спецификаций

Только намеренные расхождения. Всё, что `design/` уже отметил как правку v6 (подсказка у элемента, фокус без радиуса 8px, `ink-soft` вместо `faint`, Onest из пакета, «Скоро» в меню, «Выйти»), сделано по спецификациям и здесь не повторяется.

| # | Что | Как в спецификации | Как сделано и почему |
| --- | --- | --- | --- |
| 1 | Тест-идентификатор карточки | `balance-total` на карточке | Только на карточке с данными, не на заглушке загрузки, ошибки и «нет данных». Иначе e2e (`toBeVisible`, затем `innerText`) читает заглушку без числа |
| 2 | Нажатие мышью на карточку | «Нажатие переключает подсказку» | Мышь: наведение открывает, клик не закрывает (иначе клик сразу после наведения гасит только что открытую подсказку). Касание и клавиатура (Enter, Space) переключают, как в спецификации |
| 3 | Карточка показателя в DOM | Вся карточка это `<button>` | Карточка это `div`, внутри на всю площадь `<button data-testid="figure-tip-trigger">`: тест tester ищет триггер внутри `balance-total`. Доступное имя то же («Остаток на счетах, 2 282 658,55 ₽») |
| 4 | Предзагрузка шрифтов | `<link rel="preload">` для `cyrillic-600` и `cyrillic-800` | Не сделана: Vite хэширует имена файлов шрифтов, статическая ссылка в `index.html` невозможна без плагина. `font-display: swap` есть. Вернёмся при оптимизации загрузки |
| 5 | Строка пояснения при нулевом остатке «В банке» | Текст подстроки указан только для общей карточки («на счетах пусто») | Для карточки «В банке» взят текст «в банке пусто» (по аналогии) |
| 6 | Подсказка-сноска «Наведите или нажмите…» | Под карточками всегда | Скрыта в состояниях ошибки и «нет счетов», где карточек с цифрами нет |
| 7 | Верхняя панель до 820px, вторая и третья ленты | Подпункты активной группы отдельной третьей лентой | Подпункты стоят в той же ленте после пункта группы (`display: contents`). Готовых групп на этапе 0 нет, поэтому третья лента не проверена глазом. Доделать с первой готовой группой (этап 3) |
| 8 | Плашка «Скоро» в узкой ленте | 11px без отступов | Без фона и отступов, цвет и размер плашки сохранены |
| 9 | Баланс в шапке (`.bal`) | С этапа 1 на всех экранах кроме Рабочего стола | Не реализован: других готовых экранов нет |
| 10 | Нет сети | Полоса при потере связи | Определяется по `navigator.onLine` (события `online` и `offline`), не по неудачным запросам. Сбой запроса при онлайн-статусе показывает ошибка экрана |
| 11 | Mock-сессия | Токен хранит клиент Supabase, своего в `localStorage` нет | Только в mock-режиме (нет `VITE_API_URL`) почта лежит в `sessionStorage`, чтобы перезагрузка не выбрасывала разработчика на вход. В боевом режиме своего хранилища нет |
| 12 | Версии | | TypeScript 5.9 и ESLint 9: `openapi-typescript` и `eslint-plugin-jsx-a11y` пока не поддерживают TypeScript 6 и ESLint 10 |
| 13 | Размер бандла | | `@supabase/supabase-js` в основном чанке (около 540 КБ, 156 КБ gzip). Разделение на чанки отложено: на этапе 0 один экран |
| 14 | Тест-идентификаторы Рабочего стола | Designer и tester называют одни элементы по-разному (`balance-chart` и `balance-trend`, `advice-why-panel` и `advice-why-body`, `month-profit-margin` и `month-margin`, `dashboard-subtitle` и `page-subtitle`) | Оба имени стоят на вложенных друг в друга элементах |
| 15 | Изменение за неделю | Одна кнопка «+3,9% за неделю» | Две кнопки с отдельными подсказками: `+15 400 ₽` (`week_change`) и `+3,9% за неделю` (`week_change_pct`), по итоговому контракту. Рубли первыми: так читает e2e tester |
| 16 | «Советы» без данных | Только «Пока всё в порядке» | При истории короче 7 дней «Пока мало данных» (см. запрос в handoff) |
| 17 | Подстрока «хватит на» без значения | «расходов за месяц пока нет» | «расходов пока нет»: окно расчёта 28 дней |
| 18 | Подстроки месяца «прогноз», «к августу» | Отдельные кнопки | Не сделаны: backend их не отдаёт на этапе 2. Подстрока рентабельности есть |
| 19 | Строки `details` в подсказке | Под чертой | Без `data-testid="figure-tip-row"`, свой `figure-tip-detail`: иначе e2e сравнивает строки с `breakdown` и находит лишние |
| 20 | Этап 5, сортировка прайса | `aria-sort` на колонке; переключатель порядка в заголовке колонки | Две кнопки сортировки в панели над списком (`price-sort-margin`, `price-sort-profit`) с `aria-sort` на самой кнопке: так читает e2e tester на всех ширинах. Строго `aria-sort` допустим только на заголовке столбца; у `th` таблицы он тоже стоит. Порядок меняет повторный клик |
| 21 | Этап 5, группа позиции в техкарте | `Segmented` из трёх, на 390 `select` | Как в спецификации (переключение по `max-width: 820px`, а не 560px: диалог становится листом на 820) |
| 22 | Этап 5, подписи долей в сегментах полосы цены | Сегмент раскрывает подсказку по наведению | Сегменты без подсказки (`aria-hidden`, `data-no-tip`): те же числа и подсказки в легенде (кнопки). Нет второго набора фокусных элементов |
| 23 | Этап 5, доля части в легенде | Доля в подсказке суммы | Отдельная кнопка с долей рядом с суммой (`price-legend-share`, свой `FigureTip` с `share_pct`): так требует таблица testid |
| 24 | Этап 5, `no_expenses` в карточке услуги | В спецификации нет | Строка в баннере «Не хватает»: «Нет расходов за месяц: загрузите выписку. Без них прибыль услуг не считаем.» и ссылка «Загрузить выписку». Нужен текст designer |
| 25 | Этап 5, позиция без цены закупки | `missing[]` называет код | Название позиции берётся из `details` части («Нет цены закупки: …»): отдельного поля в ответе нет (запрос в handoff) |
| 26 | Этап 5, признаки статей `in_service_recipes`, `doctor_percent` | Задаёт команда | Экрана правки категорий нет, интерфейса для признаков нет (контракт: «правка из интерфейса позже») |
| 27 | Этап 5, `npm run gen:api` | `openapi-typescript <файл>` | `scripts/gen-api.mjs` переносит вложенные `$defs` тел запросов в `components.schemas` (в экспорте backend их `$ref` не разрешаются). Запрос backend в handoff |
| 29 | Этап 5, `net_profit = null` без `recipe` (нет выписки) | Не описано | Полоса не рисуется, текст «Полоса появится, когда будут расходы за месяц» |

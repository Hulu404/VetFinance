# Сайт ВетФинанс

Лендинг и юридические страницы сервиса. Одна Node-программа раздаёт статику и
принимает заявки с формы, пересылая их в Telegram.

## Что внутри

```
public/
  index.html        лендинг (вся вёрстка, картинки и видео внутри файла)
  privacy.html      политика конфиденциальности
  consent.html      согласие на обработку персональных данных
  offer.html        публичная оферта
  404.html          страница «не найдено»
  robots.txt, sitemap.xml
  assets/
    site.js         общий скрипт всех страниц: cookie-согласие, Метрика, возврат к форме
    favicon.svg     иконка сайта
server.js           сервер: статика + POST /api/lead → Telegram
railway.json        параметры деплоя на Railway
```

Как страницы связаны между собой:

- с лендинга в подвале и в форме — ссылки на все три документа;
- ссылки из формы помечены `?r=form`, поэтому «На главную» с документа возвращает
  сразу к форме, а не в начало страницы;
- cookie-баннер и Яндекс Метрика живут в `assets/site.js` и одинаково работают на
  всех четырёх страницах: решение посетителя запоминается в `localStorage` под
  ключом `vf-ck` и действует на весь сайт;
- сервер отдаёт страницы и по коротким адресам: `/privacy` равно `/privacy.html`.

## Запуск локально

```bash
npm run dev              # http://localhost:3000
```

Сервер сам перезапускается, когда вы правите `server.js` или что-нибудь в `public/`
— достаточно обновить страницу в браузере. Зависимостей нет, `npm install` не нужен.
Нужен Node 20 или новее.

`npm run dev` подхватывает файл `.env`, если он лежит в корне проекта:

```bash
cp .env.example .env     # вписать токен бота и chat_id, при желании другой PORT
```

Без `.env` сайт всё равно поднимется, а форма заявки будет отвечать «Приём заявок
временно недоступен» — сами заявки при этом видно в консоли.

Занят порт 3000 — запустите на другом:

```bash
PORT=3100 npm run dev            # bash
$env:PORT="3100"; npm run dev    # PowerShell
```

`npm start` — то же самое, но без слежения за файлами: этой командой сайт запускается
на Railway.

## Деплой на Railway

1. Создать проект из этого репозитория — Railway сам определит Node и выполнит `npm start`.
2. В разделе **Variables** задать:
   - `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather);
   - `TELEGRAM_CHAT_ID` — куда слать заявки: ваш личный id (узнать у
     [@userinfobot](https://t.me/userinfobot)) или id группы вида `-1001234567890`.
     Бота нужно заранее добавить в эту группу.
3. `PORT` Railway подставляет сам — задавать не нужно.
4. Проверка живости настроена на `/healthz`.

Если переменные не заданы, форма вернёт посетителю «Приём заявок временно
недоступен», а в логах будет предупреждение. Сама заявка при этом всё равно
пишется в лог строкой `ЗАЯВКА {...}` — ни одна не теряется.

## Что настроить перед запуском

- **Домен.** В `canonical`, Open Graph, `robots.txt` и `sitemap.xml` указан
  `https://vetfinance.ru` — поменяйте на боевой адрес, если он другой.
- **Яндекс Метрика.** В `public/assets/site.js` вверху есть `METRIKA_ID`. Пока строка
  пустая, счётчик не загружается вообще. Впишите номер — и он будет подключаться
  только после согласия посетителя в cookie-баннере, как обещано в политике.
- **Картинка для соцсетей.** В `og:` тегах пока нет `og:image`. Положите картинку
  1200×630 в `public/assets/` и добавьте на неё ссылку.

## Как работает форма заявки

Браузер отправляет `POST /api/lead` с JSON: имя, телефон, клиника, программа учёта,
список банков и адрес страницы. Сервер проверяет поля ещё раз (браузерной проверке
доверять нельзя), ограничивает частоту — не больше 5 заявок с одного IP за 10 минут —
и отправляет сообщение в Telegram. Токен бота остаётся на сервере и в браузер не
попадает.

Ответы сервера: `200` — заявка ушла, `400` — не прошли проверку поля, `429` — слишком
часто, `502` — Telegram не ответил, `503` — на сервере не настроены переменные.
Всё, кроме `200`, лендинг показывает как «Не получилось отправить заявку» со ссылкой
на @vetfinance.
